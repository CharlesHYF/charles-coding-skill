结果汇报与进度使用本模块模板；审视规范、代码审查、方案讨论在有两个以上问题或需要用户决定时，使用 "问题描述 / 存在的隐患 / 解决方案" 三段式编号列表；日常问答使用自然段。

## 状态词
写工作或检查状态时，只用以下 10 个状态词。每个状态必须对应明确的工作或检查范围，不得用 "已" 加其他动词代替状态词。

| 状态词 | 词义 | 不得替换为 |
| --- | --- | --- |
| 已完成 | 所述范围内的动作全部结束，且没有已知结果否定该范围的完成；不自动表示已验证。 | 搞定、OK、done、基本完成 |
| 部分完成 | 只完成所述范围的一部分，必须列出未执行和执行失败的部分。 | 基本完成、大致完成 |
| 未开始 | 所述范围内尚未执行任何动作。 | 待办、TODO |
| 进行中 | 动作已经开始，但尚未结束。 | 处理中、跟进中 |
| 已验证 | 指定范围的检查实际执行并通过，必须写明方法、结果与范围。 | 已测试、应该没问题 |
| 未验证 | 明确知道指定检查尚未执行，必须说明原因。 | 理论上可行、应该可以 |
| 失败 | 动作或检查已经执行，但结果不符合要求，必须引用关键失败输出。 | 有点问题、不太行 |
| 跳过 | 有意不执行某项动作或检查，必须说明原因。 | 略过、忽略 |
| 阻塞 | 因缺少条件而无法继续，必须写明缺少的条件。 | 卡住、受阻 |
| 未确认 | 事实缺少足够证据，包括检查是否执行或结果不明，必须写明确认方法。 | 可能、大概、应该是 |

- 工作状态与验证状态分开表述，"已完成" 不得代替 "已验证"。
- 完成条件来自用户要求、项目要求与任务目标。必需检查未执行或失败时，不得写整项任务 "已完成"，必须列出未完成部分。
- 只完成代码修改时，可以限定为 "已完成：代码修改。"，并另写运行效果的验证状态，不得扩大为整项任务完成。
- 同一对象存在已知失败时，必须写明失败及其对完成范围的影响，不得用 "已完成，未验证" 覆盖失败。
- 只有明确知道检查未执行时才写 "未验证"；缺少执行记录或结果证据时写 "未确认" 及确认方法。

## 两档汇报
### 子任务进度
任务清单一项完成、一次验证跑完或遇到阻塞时，写一行进度。状态词按实际情况选择，失败或阻塞不得写成 "进行中"。

```text
<状态词>：<动作><对象>。
```

示例：

```text
已完成：补充汇报模块的状态词表。
```

### 整个任务交付
首句写状态、完成范围与结果。使用以下结果汇报模板，无内容的节删除，验证只保留实际适用的行。

```markdown
<状态词>：<完成范围与结果>。

**改动**

- <一条改动一行，写 `路径`>。

**验证**

- 已验证：<检查方法与范围> -- <结果>。
- 未验证：<未执行的检查与范围> -- <原因>。
- 失败：<检查方法与范围> -- <关键失败输出原文>。
- 未确认：<缺少证据的检查或结果> -- <确认方法>。

**未做**

- <范围内没有执行的事> -- <原因>。

**待确认**

- <由用户决定的事项或来源缺少的事实，一条一行>。
```

同一检查的证据只列一次，并说明覆盖范围。检查未执行或失败写在 "验证"，其他未执行事项写在 "未做"。"改动 / 验证 / 未做 / 待确认" 是固定节名，不换成近义词。

示例（以下文件与验证结果仅演示格式）：

```markdown
已完成：补充配置读取说明并通过文档链接检查。

**改动**

- `docs/config.md`：说明配置文件位置与读取顺序。

**验证**

- 已验证：`bash scripts/check-doc-links.sh docs/config.md` 检查该文档全部链接 -- 退出码 0，无失效链接。
```

## 分析输出格式
审视规范、代码审查、方案讨论在有两个以上问题或需要用户决定时，每个问题各占一个编号，编号内按以下三段书写：

1. **问题描述**：说明具体问题，附 `路径:行号` 或其他可定位依据。

   **存在的隐患**：说明不修改会导致的具体后果，不只写 "不规范"。

   **解决方案**：说明修改动作与位置；需要用户选择时，在本段列出编号选项。

未达到上述条件时使用自然段，不把所有日常解释强制写成分析列表。

## 汇报规则
- **关键信息先行**：结果首句写状态与完成范围；进度写动作与对象；排查先写原因或 "原因未确认"；请求决定先写待决事项；日常问答先写核心答复。
- **状态词固定**：只按状态词表表达工作或检查状态，不用近义词，不扩大状态对应的范围。
- **如实写验证**：修复效果、运行行为、检查结果必须写验证状态、方法、结果与范围。读取资料只能支持资料内容的结论，不代表运行验证。进度、建议与待决事项不强加验证状态，其中的实际效果断言仍按本条写。
- **不叙述过程**：直接写结果与证据，不复盘文件读取、搜索、尝试和内部执行顺序。
- **证据可定位**：代码证据写 `路径:行号`，提交证据写提交号，命令证据写完整命令。失败时引用关键失败输出，同一证据不重复堆列。
- **选项编号**：需要用户决定时，选项使用编号，每项写动作与后果；推荐项放第一，标 "（推荐）"。
- **不确定写明**：证据不足的事实写 "未确认"，并写确认方法；不得用 "可能"、"大概"、"应该是" 掩盖不确定。
- **不编造**：事实必须来自用户输入、文件内容或工具输出。来源缺少的内容列入 "待确认"，不得补造事实、依据或验证结果。

## 执行方式
本模块属于 "手动约定类"，靠指令遵循，无机械校验。一致性测试只核对状态词与入口链接，不判断实际回复是否符合本模块。
