# 规范模块划分
> 模块职责：定义七个规范模块各自管什么、与校验器和测试的同源关系
> 负责人：Charles
> 系统模块：skill
> 关联文件：skills/coding-standards/rules/、tools/check.sh、tests/check_consistency.sh

## 功能一：模块边界

### 功能描述
规范本体按关注点拆成七个模块，每条规则只活在一个模块里。判断一条新规则该放哪，按下表定位；跨两个模块的规则拆开写，不在两处各写一份。

| 模块 | 管什么 | 不管什么 |
| --- | --- | --- |
| common | 缩进、行尾、禁用符号、大括号、元素与空行排版、常量 | 具体语言的格式化工具配置 |
| naming | 变量、函数、布尔、集合、数据传输对象命名 | 目录与文件命名（属各语言分册） |
| text | 注释语法、文件头、篇幅、折行、措辞 | 文档结构（属 domains/docs-markdown） |
| architecture | 分层、解耦、单一入口、文件内排列顺序 | 目录结构（属各技术栈分册） |
| git | 提交粒度、提交信息、署名、分支、gitignore、交付整洁 | CI 配置（属脚手架模板） |
| process | 变更类型闸门、模块文档、AGENTS.md、子 Agent 契约 | 具体测试写法（属 domains/testing） |
| collaboration | 工作节奏、分析输出格式、确认边界、中文表达 | 代码本身的任何规则 |

### 入参要求
- 新增规则前先判定它属于哪个模块，避免同一条规则在多处出现
- 规则涉及机器校验时，同步确认 `tools/check.sh` 是否已有对应检查项

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 规则内容 | 文本 | 是 | 待归入的规范条目 |
| 是否可机器校验 | 布尔 | 是 | 决定是否需要同步改 check.sh 与回归测试 |

### 返回
- 规则归入唯一模块
- 可校验的规则同时具备 check.sh 检查项与回归测试断言

## 功能二：同源关系

### 功能描述
同一条硬约束会同时出现在规范模块、项目模板 AGENTS.md 与校验器里，这是刻意的重复：子 Agent 是隔离上下文，只认它直接读到的文件，指针式引用会在转述中丢失。重复由 `tests/check_consistency.sh` 的断言锁定，改一处漏一处会让测试变红。

### 入参要求
- 修改任一处硬约束时，同步检查另外两处
- 新增同源点时，同时新增对应断言

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 规则标识串 | 字符串 | 是 | 断言用来定位的关键文本，如 lint 范围串 |
| 同源文件清单 | 数组 | 是 | 该规则必须出现的全部文件 |

### 返回
- 一致性自检全绿
- 任一处漏改时，断言指出缺失的文件与文本

## 功能三：校验器与规则的对应

### 功能描述
`tools/check.sh` 的十二项检查各自对应规范里的确定性规则。不能机器判定的规则标注为手动约定，不在表格里假装有工具兜底。

| 检查项 | 对应规则 |
| --- | --- |
| 一 禁用字符 | common 的禁用符号 |
| 二 文件头 | text 的文件头模板与描述粒度 |
| 三 必需文件 | process 的模块文档与用例目录 |
| 四 命名 | naming 的占位名与数据传输命名 |
| 五 注释语法 | text 的块注释与 docstring |
| 六 注释篇幅与折行 | text 的篇幅上限与折行 |
| 七 注释黑话 | text 的措辞词表 |
| 八 模块访问边界 | architecture 的单一入口 |
| 九 样式注释 | languages/html-css 的样式禁注释 |
| 十 import 排版 | languages/javascript-typescript 的 import 顺序 |
| 十一 测试代码位置 | domains/testing 的测试集中放置 |
| 十二 压测脚本 | domains/testing 的压测强制与四类覆盖 |

### 入参要求
- 新增检查项时同步更新本表与 `tests/run_tests.sh` 的场景
- 检查项编号必须连续，由 `tests/check_consistency.sh` 校验

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 检查项编号 | 整数 | 是 | 在 check.sh 里的执行顺序 |
| 对应规则位置 | 路径 | 是 | 规则正文所在的模块文件 |

### 返回
- 检查项与规则一一对应
- 回归测试同时覆盖该检查的拦截与放行行为
