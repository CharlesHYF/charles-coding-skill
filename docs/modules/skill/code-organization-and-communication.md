# 代码编写组织与开发交流规范
> 模块职责：规定源码编写与组织方式、已有代码修改边界和开发交流风格
> 负责人：GPT-5
> 系统模块：skill
> 关联文件：skills/coding-standards/SKILL.md、skills/coding-standards/rules/architecture.md、skills/coding-standards/rules/collaboration.md

## 代码编写与组织规范
### 功能描述
所有新写和修改的源码默认按照统一的文件结构、定义区、业务方法顺序和注释位置编写。调整已有代码时必须保持现有行为；用户只要求整理代码或注释时，不得修改业务逻辑、接口、数据结构、命名和交互行为。

### 入参要求
- Agent 已读取项目 `AGENTS.md` 和对应语言分册
- Agent 已确认文件职责、页面顺序或业务执行流程
- 涉及代码顺序调整时，必须先确认初始化顺序和副作用不会变化

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 源码范围 | 文件或目录 | 是 | 本次新写或修改的源码范围 |
| 业务流程 | 顺序描述 | 是 | 页面展示顺序或代码执行顺序 |
| 已有行为 | 约束集合 | 否 | 修改已有代码时必须保持的接口、状态和执行时机 |

### 返回
- 符合编写与组织规范的源码文件
- 实际执行的格式化、静态检查和测试结果
- 发现但未修改的业务问题或重构建议

## 源码文件头检查
### 功能描述
校验源码文件头的职责描述、创建日期、修改日期和对应语言的注释语法。

### 入参要求
- 文件属于 `scripts/check.sh` 配置的源码扩展名范围
- 已有创建日期必须保留
- 缺少创建日期时优先从 Git 历史确认，没有可靠依据时不得编造

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 文件路径 | String | 是 | 待检查的源码文件 |
| 文件头扫描行数 | Integer | 是 | 限制文件头规则的扫描范围 |

### 返回
- 合规文件返回成功状态
- 不合规文件返回文件路径、规则名称和命中内容

## Chinese Developer 交流风格
### 功能描述
使用清晰、直接、自然的中文进行开发交流，减少无信息量的过程播报、重复结论和抽象表达。

### 入参要求
- 适用于使用 charles-coding Skill 的开发对话
- 代码、命令、API、文件路径和正式技术术语保持原样
- 不覆盖平台要求、权限边界、测试要求和用户明确要求的交付格式

### 参数
| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 任务结果 | Object | 是 | 已完成的修改或分析结论 |
| 验证证据 | Object | 否 | 测试、命令输出或源码位置 |
| 风险与遗留 | Array | 否 | 确实存在的风险或未处理问题 |

### 返回
- 先说明结果，再提供必要依据和影响
- 代码修改完成后默认只说明改动、验证结果和实际风险
- 抽象术语改写为具体职责、位置、输入、输出或行为影响

## 验收标准
- `SKILL.md` 能按任务类型引导 Agent 读取对应专项分册
- 项目模板 `AGENTS.md` 内联默认代码编写组织规则、已有代码修改边界和开发交流要求
- Vue 分册包含 `<script setup>` 的推荐排列顺序和行为保持条件
- 文件头日期格式由 `scripts/check.sh` 校验并有回归测试覆盖
- README、Skill 版本号和一致性测试同步更新
- 仓库测试与 Skill 校验全部通过
